# M7 — File-backed mapping store

Read first: `SPECIFICATION.md` section 5.4 (the contract you are implementing), section 5.1
(the SPI), Appendix A.4 (what keys look like), and `docs/adr/0011-file-backed-mapping-store.md`
(why the design is what it is). Do not deviate from spec 5.4; if you find a gap, stop and flag
it — do not invent behaviour.

Hard rules for this milestone:

- No existing golden output, conformance vector, or Appendix A algorithm may change. If any
  existing test's expected value would change, stop and flag it.
- JDK only (`java.nio`, `java.util.Base64`). No new dependencies.
- The file format in spec 5.4 is frozen on ship: implement it exactly (header line, tab-separated
  fields, `base64url` without padding over UTF-8 bytes, `\n` terminators).

## Tasks

- [ ] **Implement `FileMappingStore`** in `io.github.dconneely.alterego.store` — `public final
  class FileMappingStore implements MappingStore, AutoCloseable`, constructed only via
  `public static FileMappingStore open(Path file)`. Follow spec 5.4 exactly: exclusive
  `FileChannel.tryLock` for the store's lifetime; replay into a forward map plus per-namespace
  inverse index (mirror `InMemoryMappingStore`'s structure); append one record per newly stored
  mapping, flushed before returning; torn-tail rule on replay; `AlterEgoStoreException` (with
  file and line number where applicable) for: lock already held, wrong header, malformed
  interior line, duplicate (namespace, key), any operation after `close()`. `close()` idempotent.
  Javadoc states behaviour (single-process, growth, durability, sharing via the one instance),
  not implementation.
- [ ] **Unit tests** (`store/FileMappingStoreTest.java`), each a separate method, using
  `@TempDir`:
  - new file: `open` writes the header; `get` on the empty store is empty.
  - persistence: put mappings, `close()`, `open` again — all mappings and the uniqueness
    (value-in-use) state survive.
  - `putIfAbsent` on an existing key and `putIfAbsentUnique` returning
    `ExistingMapping`/`ValueTaken` append nothing (assert file line count unchanged).
  - torn tail: append garbage without a trailing `\n` to a valid file; `open` succeeds, ignores
    it, and the next stored mapping overwrites it (file parses cleanly afterwards).
  - corruption: a malformed interior line, a duplicate (namespace, key), and a wrong header each
    make `open` throw `AlterEgoStoreException`.
  - locking: a second `open` of the same path while the first store is open throws; after
    `close()` it succeeds.
  - closed store: every SPI method throws `AlterEgoStoreException` after `close()`;
    `close()` twice is a no-op.
  - keys/values that contain tabs, newlines, and non-ASCII round-trip intact (use
    `rawMappingKeys`-style raw strings directly through the SPI).
- [ ] **Run the contract test against it**: subclass/parameterise
  `store/MappingStoreContractTest.java` the same way the in-memory store does, with a fresh
  temp-file store per test.
- [ ] **Integration test** (`FileStoreUniquenessIntegrationTest.java`): build an `AlterEgo` with
  a `FileMappingStore` and a deliberately tiny output space (e.g. `pattern("D")`) so collisions
  occur under `unique()`; record the input→output map; close and reopen the store with a fresh
  `AlterEgo` (same salt); assert every mapping, including the collision resolutions, is
  identical. This is the promise ADR 0011 exists for — test it directly.
