# M4 — MappingStore, `stored()`, `unique()`

Ordered checklist; spec references are to `SPECIFICATION.md`. Package roots:
`io.github.dconneely.alterego` and `io.github.dconneely.alterego.store`.

**Two spec gaps resolved before this milestone started** (see `SPECIFICATION.md` sections 2.6,
5.1, 5.3): neither the raw-mapping-key opt-in nor `unique()`'s configurable retry budget had a
pinned API shape. Decided (project owner, 2026-07-26): both are `AlterEgo.Builder` options —
`rawMappingKeys(boolean)` (default `false`) and `uniqueMaxAttempts(int)` (default `64`) — applying
instance-wide, so `Transformation`'s published no-arg `unique()`/`stored()` shape (section 2.5)
stays untouched. `SPECIFICATION.md` already reflects this; implement against the updated text.

- [x] **1. `AlterEgo.Builder` additions**
  - `rawMappingKeys(boolean)` — default `false`. `uniqueMaxAttempts(int)` — default `64`;
    `build()` throws `AlterEgoConfigException` for `< 1`.
  - Both stored on `AlterEgo` and threaded through to `bind(...)`'s `DefaultTransformation` and
    (for `rawMappingKeys`) `DefaultTransformationContext`/`DefaultMappings`, so
    `context.mappings()` honours the same key convention as `stored()`/`unique()`.
  - A single shared key-computation path (e.g. `Derivation.mapKey(salt, domain, canonical, raw)`)
    used by both `DefaultMappings` and the `stored()`/`unique()` decorator logic — no duplicated
    hash-vs-raw branching.
  - Acceptance: builder rejects `uniqueMaxAttempts(0)` and negative values at `build()` time;
    default values match the spec (`false`, `64`) when unset.

- [x] **2. `InMemoryMappingStore`**
  - `ConcurrentHashMap`-backed, one forward map plus one inverse (value → key) map per namespace,
    so `putIfAbsentUnique`'s value-in-use check is O(1).
  - `get`/`putIfAbsent` need only the forward map's own atomicity (`ConcurrentHashMap.putIfAbsent`
    suffices). `putIfAbsentUnique` must check-and-write both maps as one atomic unit (a per-namespace
    lock is the straightforward, correct choice for an in-memory store — spec 5.1 does not require
    lock-freedom, only atomicity).
  - Memory grows unbounded with distinct inputs — already documented on the class from M1; no
    eviction in v1.
  - Acceptance: unit tests for `get`/`putIfAbsent`/`putIfAbsentUnique`'s three outcomes; a
    multi-threaded hammer test (many threads, a tiny-ish shared output space) asserting no two
    distinct keys ever end up with the same value and no submitted key is ever lost.

- [x] **3. Reusable `MappingStore` contract test**
  - An abstract test class (e.g. `MappingStoreContractTest`) exercising the SPI itself —
    `get`/`putIfAbsent` semantics, and `putIfAbsentUnique`'s three outcomes plus its atomicity
    under concurrent callers racing the same key and the same value — written so a future
    external store implementation (JDBC, file-backed) can subclass it and reuse the same tests
    (spec section 10 "Store contract test").
  - `InMemoryMappingStoreTest` (or similarly named) subclasses it for M4's own implementation.
  - Acceptance: the contract test class has no dependency on `InMemoryMappingStore`'s internals;
    a deliberately broken fake store (e.g. one that ignores atomicity) fails at least one
    contract test, proving the tests actually exercise the atomicity requirement.

- [x] **4. `stored()` decorator**
  - On `apply(input)`: `null` still short-circuits under `NullPolicy` exactly as before, before any
    store interaction. Otherwise: compute the canonical form and its store key
    (`Derivation.mapKey`, section 5.1/2.6); look up the key in the raw `MappingStore` (namespace =
    domain); if present, decode and return it (section 2.6 canonical forms; decode failure throws
    `AlterEgoStoreException`); otherwise run the strategy, encode the result, `putIfAbsent`, and
    decode+return whatever the store ends up holding (the local candidate, or another thread's
    value on a race).
  - Decorator algebra (section 2.5): idempotent (`t.stored().stored()` ≡ `t.stored()`).
  - `stored()`/`unique()` without a configured `MappingStore` throw `AlterEgoStoreException`
    immediately at decoration time, not per element (already partly stubbed from M1 — replace the
    "not implemented until M4" branch, keep the "no store configured" branch).
  - Acceptance: repeated calls for the same input reuse the stored output even if the underlying
    strategy is (hypothetically) non-deterministic; determinism/golden tests unaffected for
    undecorated transformations; idempotence test.

- [x] **5. `unique()` decorator**
  - The section 5.3 loop exactly: `get(key)` short-circuit; else run the strategy at retry counter
    `0` (top-level context), attempt `putIfAbsentUnique`; on `Stored` return the candidate; on
    `ExistingMapping(v)` decode and return `v`; on `ValueTaken` bump the counter, re-derive the
    context via `DefaultTransformationContext.retry(...)` (already stubbed from M1 for exactly
    this), generate a new candidate, and retry, up to `uniqueMaxAttempts`; beyond that, throw
    `AlterEgoCollisionException` naming the domain and suggesting the output space is too small.
  - Decorator algebra (section 2.5): idempotent; subsumes `stored()` both ways round
    (`t.unique().stored()` ≡ `t.unique()`; `t.stored().unique()` ≡ `t.unique()`) — model this as
    an internal mode (`NONE`/`STORED`/`UNIQUE`) that `stored()`/`unique()` only ever raise, never
    lower.
  - Acceptance: tiny-output-space test (e.g. `pattern("D")` — 10 possible outputs — `.unique()`
    over 11 distinct inputs) raises `AlterEgoCollisionException`; order-independence caveat test
    (section 5.3: undecorated transformations are order-independent; `unique()` is the documented
    exception only on an actual collision); decorator-algebra tests for all four composition
    identities.

- [x] **6. Milestone test gates**
  - Concurrent hammer test against `InMemoryMappingStore` through a real `unique()` transformation
    (not just the store directly) via a parallel stream — no duplicate outputs, no lost mappings,
    matching spec section 10.
  - `context.mappings()` (`DefaultMappings`) still uses hashed keys by default and honours
    `rawMappingKeys` — a small dedicated test, since this path isn't exercised by
    `stored()`/`unique()` at all.
  - `AlterEgoStoreException` decode-failure test: corrupt a store's raw entry (e.g. hand-construct
    a fake `MappingStore` returning unparseable text for a `LocalDate`-typed `stored()`
    transformation) and confirm decoding throws with a useful message.
  - Acceptance: `./gradlew build` green; all M4 "done when" criteria in `PLAN.md` met (tiny-output-
    space collision test raises `AlterEgoCollisionException`; multi-threaded hammer test over the
    in-memory store shows no duplicate outputs and no lost mappings; the reusable store contract
    test covers atomicity of `putIfAbsentUnique`).
